# 测试、发布与最终验收计划

阶段门禁：G0范围确认；G1规则与参考版本确认；G2页面／技术契约评审；G3纵向切片贯通；G4功能及异常回归；G5解压包、兼容、恢复及部署检查；G6产品／规则／用户最终验收。缺少历史记录不能追溯标记通过。

|测试层|检查内容|当前依据|
|---|---|---|
|规则／数据|金额、职业、卡牌、轮次、胜负、非法输入|npm test及独立数据夹具|
|交互|正常／取消／不足现金／破产／退出／旁观者|reference-ui、terminal、card-contract等脚本|
|显示|真实中文、最大金额、开关／刷新、遮挡、字体失败|display-bugs、attachment-regressions、视觉区域夹具|
|联机|双客户端轮序、重复请求、断线、恢复、持久化|online、observer、rooms测试|
|离线／打包|完整包index、本机房间、无外部依赖、哈希一致|standalone和index-local记录|
|兼容／非功能|真实file入口、浏览器／系统、容量、性能、安全及可访问性|尚无完整验收矩阵，不能据现有测试宣称通过|
|用户验收|真实下载、解压、开局、买卖、借还、刷新、快车道和终局|需保存具体包与实际用户结果|

执行入口见 package.json。当前最近证据为 ../../../audit/validation-latest.json 和 ../../../audit/display-fixes-v0.6.4.json：记录353项单元测试、27套浏览器检查通过。这是已有报告的引用，本轮文档工作没有重新执行游戏测试。95个实际买卖牌布局扫描是额外局部检查，不是95个完整游戏场景。

验收要求：每条需求有明确通过标准和证据；阻止启动、数值错误、重复结算、丢档等阻断问题关闭；主要流程无阻塞；已知差异有明确处理结论；交付包与受测包哈希相同；指定的系统／浏览器／真实入口通过；产品与规则审阅者记录结论；用户UAT通过或明确接受遗留项。容量、性能、安全等指标必须先确定目标再实测，不能编造“已通过”。

原版完全一致是额外且更强的验收：规则、数据、文案、素材、布局、交互和例外状态均需版本对应的参考证据；局部像素摘要与单元测试不足以证明。当前 npm run release:check 对该范围保持阻断。

验收记录模板：候选版本／提交／ZIP SHA、验收范围、环境、需求与场景ID、预期／实际、证据链接、缺陷ID、遗留差异、结论（通过／不通过／有条件通过）、条件、验收职责人、日期。禁止把空白模板当成签字记录。

发布记录模板：构建命令、依赖与Node版本、配置、存档备份、启动／健康检查、下载地址与SHA、回退版本、存档兼容限制、操作者及时间。线上域名部署状态必须实际验证，不能用代码推送代替已部署。
