# 维护与变更流程

用户反馈→缺陷编号→复现及影响分析→更新需求／规则／设计／契约→实现→针对性测试→影响回归→受测包校验→用户复验→关闭并归档。

现有实例：v0.6.3本地入口、报表重叠和骰子显示；v0.6.4股票金额、快车道异步布局和棋盘遮挡。对应记录见RELEASE-NOTES.md、audit/attachment-fixes-v0.6.4.md及测试日志，不将曾经修复等同于永不回归。

缺陷记录格式：ID｜发现版本／SHA｜环境／入口｜步骤｜预期／实际｜影响及严重度｜负责人｜状态｜修复提交｜验证证据｜回归范围｜用户复验。初始状态“待复现”，随后为已复现／处理中／待验证／待用户复验／关闭／重新打开；没有证据不直接关闭。

变更请求格式：理由、影响需求、规则与数据、页面和接口、旧存档兼容、替代方案、测试策略、决定人和版本。未批准写待决定。维护阶段持续更新来源和已知差异，保留历史版本及不可变测试记录。
