# 交互与视觉开发契约

页面状态清单：标题、房间列表、建房、等待／准备、逐人梦想选择、开始回合、掷骰和移动、选择牌堆、机会／市场／支出等事件、股票份数、借款确认、债务选择／偿还、资产出售、进入快车道、投资结果、破产重整／出局、胜利／全员结束、退出确认、断网恢复、棋盘查看。

每个页面规格必须记录：状态ID、进入条件、显示数据、主／次操作、按钮坐标与命中区域、可输入范围、取消去向、是否结算、刷新后的恢复方式、旁观者状态、手机显示策略、加载失败与错误提示、参考截图及来源版本。现有页面登记见 ../../../audit/reference-coverage.json；不能把清单存在当成全部规格已批准。

当前舞台为固定1024×768，页面上边距25；小屏横向滚动。卡片和报表为模型外的显示层，不能通过隐藏卡片来改变游戏结算。实际几何集中在 reference-layout-data.js；视觉原图与来源见 assets/reference/SOURCES.json。

显示约束：中文不能直接套用短英文标签的宽度；金额与标签分栏或分行，保留完整数值；字体失败可回退，不能阻止画布启动；Canvas与DOM必须同步；异步close事件不能写回过期布局；查看棋盘保存输入，不推进轮次。每个可见金额字段应验证允许的最大值。

已知样例与基线：../../../audit/screenshots/v0.6.4/，附件修复说明 ../../../audit/attachment-fixes-v0.6.4.md。单骰原图和模板锚点有证据，多骰排列仍含实现选择。仍需逐页补齐标准截图、交互录屏、不同职业／状态的文案边界以及视觉批准记录。

UX交给前端：状态表、流程、线框、取消／恢复规则。UI交给前端：尺寸、字体、颜色、图层、素材版本、溢出策略和动效时序。前端交回：实现截图、例外清单、浏览器记录。QA按状态和数值边界检验，不仅检查按钮是否存在。
