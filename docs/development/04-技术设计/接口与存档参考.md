# 当前实现的接口与存档参考

以scripts/rooms.cjs、table.js、local-rooms.js为事实来源，基线v0.6.4；后续修改需同步文档和契约测试。

## HTTP接口

|方法／路径|请求|结果／限制|
|---|---|---|
|GET /api/rooms|无|可加入房间列表|
|POST /api/rooms|name、capacity、playerName、可选password|201，房间视图及token；容量1–6|
|GET /api/rooms/:id|Authorization: Bearer 会话token|本座位视图，不返回未来牌序|
|POST /api/rooms/:id/join|playerName、可选password|视图及加入会话；检查密码和容量|
|POST /api/rooms/:id/ready|version及ready|校验会话、版本和准备状态|
|POST /api/rooms/:id/rename|version及name|开局前改名|
|POST /api/rooms/:id/start|version|仅房主；要求人员与准备满足条件|
|POST /api/rooms/:id/action|version、action、args数组|校验轮序、事件和指令参数|
|POST /api/rooms/:id/chat|消息字段见command实现与测试|聊天与游戏指令独立验证|
|POST /api/rooms/:id/leave|version|等待期房主退出关闭房间；开局后处理离开与轮序|

示例动作体：`{"version":5,"action":"roll","args":[1]}`。version必须使用最新响应，示例5不是固定值。常见失败包括参数错误400、会话失效401、越权403、房间不存在404、版本冲突409、请求过大413。失败不应在客户端自行补结算；先恢复最新状态，再决定是否重试。完整动作参数和每个错误分支继续以command及rooms测试核验，不声称已生成完整OpenAPI规范。

## 状态与存档

多人游戏：version=3、ruleset、players、active、rolled、decks、round；可包含ui、dreamSelection、over。玩家：rulesProfile、jobId、dreamId、现金、资产、贷款、pending、lastDice、阶段与历史等；详见engine.create与相应测试。pending是按kind区分的联合状态，不是任意字段通用对象。

在线磁盘包：version=1与rooms数组；默认.cashflow/rooms.json，先写临时文件再rename。客户端返回的game隐藏decks。离线房间键cashflow-local-rooms-v1，包version=1、rooms对象；桌面存档和会话还有其他键，应按app／online代码审查，不能只备份一个键就承诺全部恢复。

存档版本和规则profile须分别维护；发布时保留旧存档样本，验证刷新、升级、回退。正式可机读Schema、所有pending分支字段约束及跨版本迁移矩阵仍待技术负责人完善和评审。
