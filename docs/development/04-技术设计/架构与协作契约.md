# 架构、接口与协作规范

现有职责：engine.js负责单玩家规则；table.js负责多人轮次；reference-data.js保存机制数据；app.js／interaction.js负责用户操作与状态展示；reference-ui／classic-stage／scene-canvas负责经典界面与绘制；online.js负责房间客户端；local-rooms.js提供离线同接口适配；scripts/rooms.cjs负责在线指令校验与持久化；serve.cjs提供HTTP入口；构建脚本生成内嵌资源入口。

规则层不能依赖DOM、声音或动画完成结算；界面隐藏不能改变规则状态；在线服务决定合法指令和轮序，浏览器不应收到未来牌序；离线和在线使用同一种指令语义，但存储和座位权限不同。

接口文档最低字段：方法／路由、认证会话位置、请求字段及类型、必填与范围、版本或幂等信息、成功响应、失败状态、可重试条件、并发冲突行为、示例、对应测试。现有路由与字段事实以 scripts/rooms.cjs 和 rooms.test.cjs 为准；本文件不冒充完整API字段参考。后续接口变更必须同改客户端、离线适配、契约测试和API清单。

存档设计需记录：数据版本、规则profile、房间／玩家／轮次／pending状态、迁移策略、失败恢复和回滚兼容。已有持久化与旧存档测试；正式存档Schema、跨版本兼容矩阵和迁移演练仍待补齐。

|协作双方|交接文档|交接检查|
|---|---|---|
|产品↔策划|PRD、规则决策／差异表|触发条件和结果是否可验收|
|策划↔规则／数据工程师|规则表、字段字典、数值样例|输入、结算、边界和来源一致|
|UX/UI↔前端|状态规格、标注、素材与截图基线|取消、禁用、遮挡、长文案及失败状态明确|
|前端↔后端|API／指令契约、错误与恢复时序|鉴权、轮序、重试和重复提交一致|
|研发↔QA|需求追踪、改动影响、构建与测试数据|测试包可复现，验收结果可追溯|
|研发／QA↔发布|测试报告、缺陷状态、版本校验、部署回退|下载包与受测包一致|
|产品／用户↔QA|UAT场景、实测环境、截图与复现步骤|记录通过、不通过或带条件通过|

变更流程：提出需求／缺陷ID → 记录依据和影响 → 更新受影响契约 → 实现与代码检查 → 针对性测试 → 相关回归 → 对受测构建留存哈希 → 验收／发布。代码评审、需求批准和用户验收属于不同记录，不能互相代替。

缺陷模板：编号、版本／包SHA、系统／浏览器／缩放、入口、前置存档、操作步骤、预期／实际、截图、影响、严重度、负责人、修复提交、验证证据、状态。决策记录模板：背景、备选方案、结论或待定、理由、影响需求、证据、决定人／日期；无人确认时写“待确认”。
